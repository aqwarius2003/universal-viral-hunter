## 🚀 Ключевые возможности

- 🔍 **Автономный сбор (Scout)** — сканирование X.com с использованием cookies или токенов, дедупликация и сохранение в базу SQLite.
- 📊 **Скоринг виральности (Analyst)** — расчет показателя виральности на основе лайков, ретвитов, закладок, просмотров и времени публикации с учетом весов.
- 🧠 **Мультимодальный анализ (Editor)** — использование Google Gemini для перевода, суммаризации, выделения ключевых тезисов, тегов и выбора оптимального изображения.
- 🛡️ **Контроль качества (Critic)** — фильтрация нерелевантных тем, спама и кликбейта.
- 📱 **Умный паблишер (Publisher)** — соблюдение жестких лимитов Telegram (автоматическое компактное форматирование до 1024 символов для постов с фото и до 4096 символов для текстовых).
- 📅 **Продвинутый планировщик и режим сна** — поддержка автоматического расписания, "режима сна" (тихие часы / quiet hours), а также сборка утренних и вечерних дайджестов событий ("Пока вы спали").
- 🖥️ **Веб-дашборд управления** — визуальный интерфейс для редактирования черновиков, управления очередью публикаций и просмотра архива.

---

## 🏗️ Мультиагентная архитектура

Проект построен на базе графа агентов (State Machine) с использованием **LangGraph**:

1. **Scout Agent**: Сбор сырых твитов из X.com (через `cookies.json` или auth tokens) и сохранение в локальную БД.
2. **Analyst Agent**: Расчет математического показателя Viral Score с учетом экспоненциального затухания по времени.
3. **Editor Agent**: Использование моделей Gemini (например, `gemini-3.5-flash-lite`) для перевода, мультимодального анализа прикрепленных картинок и формирования структурированного JSON ответа.
4. **Critic Agent**: Проверка качества контента, отсеивание шума и подтверждение публикации.
5. **Publisher Agent**: Адаптация текста под ограничения Telegram, моментальная публикация или постановка поста в очередь.

## 💻 Быстрый старт (Установка и запуск)

Ниже приведены пошаговые инструкции по локальному запуску системы в ее текущем состоянии. 

### Требования
- **Python 3.11+**
- **Poetry** (менеджер зависимостей)

### Шаги установки

1. **Клонируйте репозиторий и перейдите в директорию**:
   ```bash
   git clone <URL_РЕПОЗИТОРИЯ> ai-viral-hunter
   cd ai-viral-hunter
   ```

2. **Установите зависимости**:
   ```bash
   poetry install
   ```

3. **Настройте переменные окружения**:
   Скопируйте пример конфигурационного файла и заполните его своими ключами доступа:
   ```bash
   cp .env.example .env
   ```
   *(Подробное описание параметров см. в разделе "Конфигурация")*

4. **Запустите систему**:
   Основной точкой входа является модуль планировщика `src.scheduler`. Он автоматически инициализирует базу данных, запускает веб-дашборд на порту 8000 и начинает цикл сбора постов.
   ```bash
   poetry run python -m src.scheduler
   ```

5. **Откройте веб-дашборд**:
   Перейдите в браузере по адресу: **`http://localhost:8000`**

*Примечание: По умолчанию пайплайн стартует сразу при запуске. Если вы хотите пропустить первоначальный запуск и подождать первый интервал, используйте флаг `--skip-initial`.*

## ⚙️ Конфигурация (.env)

Настройка параметров производится в файле `.env`. Основные переменные:

```env
# ==========================================
# Google Gemini API
# ==========================================
AI_API_KEY="your_gemini_api_key_here"
# Можно указать несколько моделей через запятую, первая будет основной, вторая - fallback
AI_MODEL_NAME="gemini-3.5-flash-lite, gemini-3.1-flash-lite" 

# ==========================================
# Telegram Bot & Channel
# ==========================================
TELEGRAM_BOT_TOKEN="123456789:ABCdefGHIjklMNOpqrSTUvwxYZ"
TELEGRAM_CHANNEL_ID="@your_channel_username" # Или -1001234567890 для приватных

# ==========================================
# X.com (Twitter) Auth
# ==========================================
# Опционально, если не используется cookies.json
TWITTER_AUTH_TOKEN="your_auth_token_here"
TWITTER_CT0="your_ct0_token_here"

# ==========================================
# Настройки пайплайна и планировщика
# ==========================================
MIN_VIRAL_SCORE=75.0
MAX_POSTS_PER_RUN=1
SCHEDULER_INTERVAL_MINUTES=120
# Директория монтирования SQLite БД
DB_PATH="data/tweets.sqlite"
```

## 🐳 Развертывание в Docker

Для production-развертывания на сервере предусмотрена конфигурация Docker Compose, которая использует `Dockerfile` и монтирует папку `data` для сохранения базы данных и настроек:

```bash
# Запуск в фоновом режиме
docker compose up -d --build

# Просмотр логов
docker compose logs -f

# Остановка
docker compose down
```

## ❓ Часто задаваемые вопросы (FAQ)

1. **Ошибка `Telegram server says - Bad Request: chat not found`**
   Убедитесь, что бот добавлен в администраторы Telegram-канала, а ID канала указан корректно (с `@` для публичных каналов).
2. **Как изменить порт веб-дашборда?**
   По умолчанию дашборд доступен на порту `8000` (задано в `docker-compose.yml` и `src/scheduler.py`). Для смены порта отредактируйте маппинг в `docker-compose.yml` (`"8080:8000"`).
3. **Как работает режим тихих часов (Quiet Hours)?**
   По умолчанию система не публикует посты в период с `23:00` до `07:00` (настраивается в веб-интерфейсе или `src/config.py`). Вместо этого посты накапливаются и могут быть отправлены единым "утренним дайджестом".
