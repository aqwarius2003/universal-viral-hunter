# Universal Viral Hunter

Универсальный асинхронный движок для сбора, оценки, AI-обработки и публикации контента. Проект отделяет бизнес-пайплайн от интеграций: источник данных, модель анализа, правила качества, очередь и канал публикации можно менять независимо.

Текущая готовая конфигурация использует X.com как источник и Telegram как канал публикации. Архитектура рассчитана на добавление других адаптеров без переписывания планировщика и веб-панели.

## Возможности

- сбор постов из X.com через cookies, токены или серверную авторизацию;
- дедупликация и хранение данных в SQLite;
- расчет `Viral Score` с учетом вовлеченности, просмотров и возраста публикации;
- AI-суммаризация, перевод на русский язык, тезисы, хэштеги, оценка влияния и выбор изображения;
- автоматическая проверка результата и повторная обработка невалидных черновиков;
- очередь публикаций, ручное редактирование, изменение порядка и отложенная отправка;
- Telegram-публикация текста или изображения с учетом лимитов Telegram;
- дневные и ночные дайджесты, тихие часы и автоматическая публикация из очереди;
- веб-панель с авторизацией, ролями `admin` и `editor`, мониторингом и архивом;
- Docker Compose, персистентный каталог `data` и автоматическая очистка старых записей.

## Архитектура

Основной pipeline собран как граф LangGraph:

```text
Источник -> Scout -> Analyst -> Editor -> Critic -> Publisher -> Канал
             |         |          |         |          |
           SQLite   Viral Score  Gemini   валидация  Telegram/очередь
```

Компоненты находятся в `src/ai/agents/`:

- `scout` получает и нормализует исходные записи;
- `analyst` вычисляет метрики и отбирает кандидатов;
- `editor` возвращает структурированный AI-результат;
- `critic` проверяет формат и качество черновика;
- `publisher` форматирует контент, публикует его или сохраняет в очередь.

Границы для расширения:

- новый источник подключается на уровне Scout;
- новая модель или провайдер меняется в Editor и настройках моделей;
- новый канал публикации добавляется рядом с Telegram sender;
- общие правила очереди, дайджестов и планировщика остаются неизменными.

## Быстрый старт

### Требования

- Python `3.11` - `3.14`;
- Poetry 2.x;
- API-ключ Google Gemini;
- Telegram bot с правом публикации в канале;
- доступ к X.com, если используется штатный Scout.

### Локальный запуск

```bash
git clone <URL_РЕПОЗИТОРИЯ> universal-viral-hunter
cd universal-viral-hunter
poetry install
cp .env.example .env
poetry run python -m src.scheduler
```

После запуска откройте `http://localhost:8000`. Если `.env` еще не заполнен, веб-мастер настройки создаст администратора и поможет сохранить основные параметры. Секреты не нужно коммитить в репозиторий.

Полезные команды:

```bash
# Не запускать первый сбор сразу
poetry run python -m src.scheduler --skip-initial

# Изменить интервал сбора
poetry run python -m src.scheduler --minutes 60
poetry run python -m src.scheduler --hours 2

# Вручную создать дайджест и отключить веб-панель
poetry run python -m src.scheduler --digest-now
poetry run python -m src.scheduler --no-dashboard
```

### Docker

Docker-контейнер по умолчанию запускает тот же планировщик:

```bash
docker compose up -d --build

docker compose down
```

Веб-панель будет доступна на `http://localhost:8000`. Каталог `./data` монтируется в контейнер и сохраняет базу, системные настройки и cookies X.com между обновлениями.

Для cloud-варианта используйте `docker-compose.cloud.yml`. Подробный сценарий production-развертывания, HTTPS, резервного копирования и обновления описан в [DEPLOY.md](DEPLOY.md).

## Конфигурация

Начальные значения находятся в [.env.example](.env.example). Основные параметры:

```env
AI_API_KEY=your_gemini_api_key
AI_MODEL_NAME=gemini-3.5-flash-lite,gemini-3.1-flash-lite

TELEGRAM_BOT_TOKEN=your_bot_token
TELEGRAM_CHANNEL_ID=@your_channel

TWITTER_AUTH_TOKEN=your_auth_token
TWITTER_CT0=your_ct0_token
TWITTER_PROXY_URL=

DB_PATH=data/tweets.sqlite
MIN_VIRAL_SCORE=75
MAX_POSTS_PER_RUN=1
SCHEDULER_INTERVAL_MINUTES=120
SCOUT_INTERVAL_MINUTES=15
APP_TIMEZONE=auto
```

Полный набор параметров включает настройки запросов X.com, задержки AI, лимиты дайджеста, тихие часы, стратегию сортировки очереди и отображаемые метрики. Их можно менять в веб-панели администратора. Значения из базы загружаются при старте и дополняют переменные окружения.

## Безопасность

- при первом запуске создается учетная запись администратора;
- пароли хэшируются через PBKDF2-HMAC-SHA256;
- сессии подписываются HMAC-SHA256;
- после пяти неудачных входов IP блокируется на 15 минут;
- настройки и резервная копия защищены ролью `admin`;
- `editor` может работать с очередью и публикациями, но не видит системные секреты;
- для открытого доступа через интернет используйте HTTPS reverse proxy;
- замените `SECRET_KEY` на уникальное значение и не публикуйте `.env`, `data/` или `cookies.json`.

Никогда не передавайте пароль X.com или Telegram-токены в issue, логи и git. Для production рекомендуется ограничить доступ к порту `8000` reverse proxy или firewall.

## Тесты

```bash
poetry run pytest
```

Тесты покрывают агентов, скоринг, авторизацию, базу данных, API, дайджесты, мультимодальный Editor и пакетную публикацию.

## Структура проекта

```text
src/
  ai/agents/       LangGraph-агенты pipeline
  analytics/       Скоринг и аналитика
  telegram/        Telegram sender
  web/             HTTP API и веб-панель
  config.py        Настройки и расписание
  db.py            SQLite и очередь
  digest.py        Генерация дайджестов
  scheduler.py     Планировщик и фоновые циклы
tests/             Автоматические тесты
data/              Персистентные данные, создается при запуске
```
