# 🚀 Руководство по безопасному развертыванию AI Viral Hunter

Полное руководство по развертыванию в Production на Linux VPS (Ubuntu / Debian / Alma / CentOS) с поддержкой **Zero-Env холодного старта**, веб-мастера настройки, ролевого доступа (RBAC), авторизации в X.com с IP сервера и персистентного хранения данных.

---

## ⚡ Быстрый старт: Zero-Env за 2 минуты

Вам **не нужно** вручную создавать или редактировать `.env` файл перед первым запуском. Приложение спроектировано для безопасного холодного старта из «коробки».

### 1. Клонируйте репозиторий на сервер
```bash
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ> ai-viral-hunter
cd ai-viral-hunter
```

### 2. Запустите контейнер через Docker Compose
```bash
docker compose up -d --build
```

### 3. Откройте веб-интерфейс
Перейдите в браузере по адресу:
```text
http://IP_ВАШЕГО_СЕРВЕРА:8000
```
> [!NOTE]
> При первом открытии автоматически запустится **Web Setup Wizard (Мастер первоначальной настройки)**.

---

## 🧙 Мастер первоначальной настройки (Setup Wizard)

При первом старте система обнаружит отсутствие администратора и API-ключей и предложит пройти 3 простых шага:

1. **Шаг 1: Аккаунт Администратора**
   - Придумайте логин администратора (от 3 символов).
   - Задайте надежный пароль (минимум 8 символов).
2. **Шаг 2: Интеграция с Google Gemini**
   - Введите ваш Gemini API Key.
   - Модели по умолчанию: двухмодельная архитектура `gemini-3.5-flash-lite, gemini-3.1-flash-lite` (15 RPM / 500 RPD на каждую модель, авто-fallback и изолированная мультимодальность). При наличии платного API можно указать любые модели через запятую.
3. **Шаг 3: Публикация в Telegram**
   - Введите Telegram Bot Token (полученный от [@BotFather](https://t.me/BotFather)).
   - Укажите канал для публикаций (например, `@my_ai_channel` или числовой ID `-100...`).
   - *Важно: добавьте вашего бота администратором канала с правом публикации сообщений.*

Нажмите **«Завершить настройку и войти»**:
- Настройки мгновенно сохраняются в базу данных SQLite (`./data/tweets.sqlite`) и синхронизируются с файлом `.env`.
- Создается защищенная сессия администратора.
- Фоновый планировщик немедленно активируется и начинает отслеживать тренды.

## 𝕏 Авторизация в X.com с IP сервера (Нидерланды vs Грузия)

### В чем проблема при входе с домашнего ПК?
Если вы экспортируете cookies из браузера в Грузии и передаете их на сервер в Нидерландах, защитная система X.com (Twitter) обнаруживает резкую смену геопозиции и ASN/провайдера (Geo-anomaly / Session Hijacking defense) и сбрасывает сессию (`auth_token` аннулируется).

### Решение: Авторизация прямо с VPS
В AI Viral Hunter встроен механизм серверного входа через `twifork`:

1. Перейдите во вкладку **«⚙️ Настройки»** в дашборде.
2. В блоке **«𝕏 Вход в X.com (Twitter) прямо с сервера»**:
   - Введите ваш **Логин X** (Username или Email).
   - Введите **Пароль X**.
   - *(Опционально)* Укажите дополнительный Email, если Twitter запрашивает его при авторизации с нового устройства.
   - *(Опционально)* Укажите Proxy (`http://user:pass@host:port`), если вы хотите использовать резидентный прокси.
3. Нажмите **«⚡ Войти в X с сервера»**.
4. **Если X запросит 2FA / код подтверждения**:
   - На экране автоматически появится модальное окно: *«Подтверждение входа в X.com»*.
   - Проверьте почту или SMS, введите 6-значный код и нажмите «Подтвердить».
5. Сессия будет сформирована **с IP-адреса вашего VPS** и надежно сохранена в `./data/cookies.json`.

## 👥 Роли и разграничение прав доступа (RBAC)

В системе предусмотрено два типа учетных записей:

| Возможность | 👑 Администратор (`admin`) | ✍️ Редактор (`editor`) |
|---|:---:|:---:|
| Просмотр очереди и опубликованных постов | ✅ | ✅ |
| Редактирование текстов, заголовков и времени постов | ✅ | ✅ |
| Изменение порядка очереди (Drag & Drop / стрелки) | ✅ | ✅ |
| Кнопка немедленной публикации («Опубликовать сейчас») | ✅ | ✅ |
| Вкладка «📊 Мониторинг» (светофоры интеграций и история сборов) | ✅ (полная информация) | ✅ (без системных отладочных данных) |
| Вкладка «⚙️ Настройки» (Gemini API, Telegram Bot Token) | ✅ | ❌ (скрыта в UI и заблокирована по API 403) |
| Управление пользователями (создание, удаление, смена паролей) | ✅ | ❌ (заблокировано по API 403) |
| Авторизация и смена учетных данных X.com | ✅ | ❌ (заблокировано по API 403) |
| Скачивание резервной копии базы данных (Backup) | ✅ | ❌ (заблокировано по API 403) |

Добавить редактора администратор может в любой момент в разделе **«Настройки» → «Пользователи и права доступа»**.

## 🔒 Безопасность в Production

1. **Защита от перебора паролей (Brute-force Rate Limiter)**:
   - 5 неудачных попыток входа с одного IP блокируют авторизацию на 15 минут (HTTP 429 Too Many Requests).
2. **Криптографическая защита сессий**:
   - Пароли хэшируются с использованием `PBKDF2-HMAC-SHA256` (100 000 итераций, уникальная 32-байтная соль).
   - Сессионные токены подписываются `HMAC-SHA256` с уникальным 256-битным секретным ключом, генерируемым для каждой инсталляции и сохраняемым в БД.
3. **Маскирование чувствительных данных**:
   - В API и интерфейсе ключи API Gemini, токены Telegram и пароли отображаются в маскированном виде (`AIzaSyD...****`).
   - При сохранении настроек скрытые маски не перезаписывают реальные секреты.

## 🌐 Настройка HTTPS через Reverse Proxy

Для защиты паролей и сессий при работе через интернет рекомендуется настроить SSL/HTTPS.

### Вариант 1: Caddy (Рекомендуется — настройка за 1 минуту)
Установите Caddy:
```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install caddy
```

Создайте `/etc/caddy/Caddyfile`:
```caddy
your-domain.com {
    reverse_proxy 127.0.0.1:8000
}
```
Перезапустите Caddy:
```bash
sudo systemctl restart caddy
```
*Caddy автоматически выпустит и будет продлевать бесплатный SSL-сертификат Let's Encrypt.*

### Вариант 2: Nginx
```nginx
server {
    server_name your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 🔄 Обновление версий без потери данных

Все данные приложения изолированы в примонтированном каталоге `./data`:
- `./data/tweets.sqlite` — База данных (посты, очередь, пользователи, настройки).
- `./data/cookies.json` — Авторизованная сессия X.com.

### Обновление Google Cloud VM из Windows

После изменения кода в рабочем каталоге `D:\ai-viral-hunter` запустите в PowerShell:

```powershell
.\deploy_to_cloud.ps1
```

Скрипт автоматически:
1. Создаст архив проекта без `.env` и `data`.
2. Сохранит текущий каталог `data` на VM в `data/backups/`.
3. Загрузит новый код через `gcloud compute scp`.
4. Пересоберет и перезапустит `docker-compose.cloud.yml`.
5. Покажет состояние контейнера.

Параметры VM можно изменить:

```powershell
.\deploy_to_cloud.ps1 -Instance ai-viral-hunter -Zone us-east1-b
```

Важно: запускать скрипт нужно из корня проекта. Файл `.env` и каталог `data` на VM не перезаписываются.

Для обновления проекта до последней версии выполните:
```bash
git pull
docker compose up -d --build
```
> [!IMPORTANT]
> При обновлении контейнер пересобирается с новым кодом, а каталог `./data` остается нетронутым. Никакие посты, настройки, пользователи и сессии не сбрасываются.

### Проверка после обновления

```powershell
gcloud compute ssh ai-viral-hunter --zone=us-east1-b --command="cd ~/ai-viral-hunter; sudo docker compose -f docker-compose.cloud.yml ps"
```

```powershell
gcloud compute ssh ai-viral-hunter --zone=us-east1-b --command="cd ~/ai-viral-hunter; sudo docker compose -f docker-compose.cloud.yml logs --tail=100"
```

### Восстановление данных

На VM список резервных копий:

```bash
ls -lh ~/ai-viral-hunter/data/backups
```

Для восстановления выбранной копии остановите контейнер и распакуйте архив поверх `data`:

```bash
cd ~/ai-viral-hunter
sudo docker compose -f docker-compose.cloud.yml down
tar -xzf data/backups/data-YYYYMMDD-HHMMSS.tar.gz -C data
sudo docker compose -f docker-compose.cloud.yml up -d
```

## 📦 Резервное копирование и восстановление

### Скачивание бэкапа
- В веб-интерфейсе: вкладка **«⚙️ Настройки»** → карточка **«📦 Резервное копирование данных»** → кнопка **«Скачать резервную копию базы данных»**.
- Либо прямой вызов по API (требуются права администратора):
  ```bash
  curl -H "Authorization: Bearer <TOKEN>" http://localhost:8000/api/system/backup -o backup.sqlite
  ```

### Восстановление из бэкапа
1. Остановите контейнер:
   ```bash
   docker compose down
   ```
2. Скопируйте ваш файл бэкапа:
   ```bash
   cp backup.sqlite data/tweets.sqlite
   ```
3. Запустите контейнер:
   ```bash
   docker compose up -d
   ```
